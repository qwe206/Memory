# 世界书进度为准，移除聊天来源说明 · 2026-10-29

用户明确撤回 1.0.12 的按文件总结进度及文件来源说明：要求回到老 Amily 的世界书楼层进度逻辑。用户确认已把“前 N 楼篇章编撰已完成”和末尾“前 N 楼总结已完成”两处都改到 570，并删除后续总结。

本轮版本为 Memory 1.0.13，基于 1.0.12 修复。不要再执行工作区 qa-tools 中此前的一次性修改脚本。

## 根因与修复

1.0.12 读取世界书后仍参考 story.files 的 summarizedThrough、skipThrough 和 MemoryFiles 元数据，以较大值推进，导致用户手动回退无效。本轮删除这些总结进度 API 和调度分支。自动小总结、批量总结、手动写入、首页进度及自动隐藏都直接读取当前活动总结末尾的数字进度，不恢复旧缓存。

小总结从世界书进度的下一楼继续；按当前聊天长度、保留楼层数和整批阈值判断。不会再轮询历史聊天文件补总结，也不会在原文、总结正文、向量总结正文中新增聊天文件名或来源行。归档、回溯、向量绑定和分块编辑仍保留；文件记录只用于记忆归属，不决定总结进度。

小总结生成时捕获世界书正文快照；生成后、写入前检查最新正文。期间用户手动回退进度或修改正文时，过期生成结果停止保存，向量写入前也检查。

## 旧来源清理

仅识别并清理插件自动生成的“来源聊天文件：…；本地第…楼”行、MemoryFiles / MemorySource 注释及旧来源标签；普通正文提到 report.txt 等文件名保留。原文预览只显示楼层。

自动或手动小总结开始前，会先备份并清理当前活动总结中的旧来源说明；即使未达到总结阈值，也只清理说明，不改两处楼层标记或剧情事实。归档原件不批量重写，恢复出的活动总结清理来源。现有通用大总结格式可继续解析，新生成大总结恢复数字楼层范围，不再保存各文件进度。
