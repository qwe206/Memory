# 文件记忆接续简化 · 2026-10-28

本轮版本为 Memory 1.0.12，基于 1.0.11 进行以下简化。
用户否定上一版全局累计楼层、续写段和跨文件总结依赖，明确同意改为以下简单规则。

- 未归档时，新聊天继续当前剧情的世界书总结与向量绑定；归档后新聊天空白；回溯恢复总结及向量快照。
- 每个聊天文件只记录自己的已总结位置。新内容按“聊天文件＋本地楼层”标注，不分配累计剧情楼层或续写段。
- B 的尾部待处理，不阻止 C 的自动或手动总结。自动检查先处理当前文件，再尝试其他文件；单个旧文件失败会通知并保留进度。
- 当前文件仍遵守整批阈值和保留尾部；旧文件允许补不足一批的尾部。关闭自动小总结不会仅因换聊天而调用模型。
- 手动和批量总结只处理所选当前文件，不递归要求先总结其他文件。
- 世界书小总结保留来源文件；跨文件大总结显示来源列表，不伪造跨文件楼层范围。
- 世界书内保留一份按文件的进度记录，合并大总结时一起保留。该记录用于刷新、归档回溯和保存成功后的恢复；不增加用户开关。
- 旧“独立聊天记忆”控件、监听和默认值已移除；旧配置里的该字段不再影响集合选择。已有向量和绑定不删除。
- 全局知识库的绑定、开关和编辑规则保持原有行为。

保存可靠性：读取历史文件不切换 ST 当前聊天；生成后检查原文指纹、当前聊天和归档状态；世界书保存从服务器回读确认，失败清除可能过期的缓存并保留进度；只存向量时依赖原有写入回读确认。原文变化、读取失败、写入失败、取消均不标记完成。

兼容：旧发布版的文件偏移信息只用于迁移旧进度；旧总结正文不自动改写。旧归档与上一轮本地草稿可迁移为文件进度；跨文件回溯不重新生成归档后可能变化的历史原文尾部。

验证：108 项 Node 测试通过，覆盖文件独立进度、旧尾部失败不阻塞新文件、短尾部、重试、原文变化、跨文件两轮大总结、进度记录保留、归档回溯、隐藏、只存向量、移除开关与旧配置兼容。浏览器模拟覆盖 320/375/1280 宽度的旧开关移除、接续说明、归档隔离、自动接续、按文件编辑和绑定管理。未接触用户真实聊天数据或真实模型服务。
